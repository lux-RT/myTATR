# PubTables-1M 固定千图双版本评估

本实验使用预训练模型，不重新训练。默认从官方 test 的 93,834 个表格 ID 中，按 ID 排序后使用 Python `random.Random(42).sample(..., 1000)` 无放回抽取。名单在推理前保存，不能根据识别结果换图。

## 两套流程

| 项目 | 官方评价条件基线 | 当前 OCR 系统 |
|---|---|---|
| 权重 | 微软发布的 HF TATR 结构识别权重 | 同一份权重 |
| 预处理 | 固定官方实现：最长边 1000、PIL 默认插值、ImageNet 归一化 | 原有 AutoImageProcessor 配置 |
| 框筛选 | 包含 no-object 的完整 softmax argmax，官方阈值 | 原有 Transformers 后处理，阈值 0.5 |
| 词信息 | 官方词文本及图片坐标 | PP-OCRv6 small，输入放大 2 倍 |
| 单元格及文字 | 官方后处理 | 原有 fuse()，先构造结构再分配文字 |
| 评价 | 相同的官方 GT 单元格及 GriTS/AccCon 函数 | 相同的官方 GT 单元格及 GriTS/AccCon 函数 |

差值同时包含预处理、OCR 与文字后处理的影响，不能全部归因于 OCR。这里的“官方评价条件基线”采用 HF 发布权重和当前推理库，没有宣称与作者旧版 DETR 运行时逐层数值等价。

## 本机运行

在 `myTATR` 目录使用相邻下载环境的 Python。先确保官方 test 图片、test XML、文件列表及词信息原始压缩包已经下载。数据版本固定为 `35b1c097807e0b07ec5313879b85956b7b3890db`。

词信息文件为 `PubTables-1M-Structure_Table_Words.tar.gz`，4,174,842,415 字节，SHA-256：

```text
dbab74fa5fe5354cca229533efe7e374b58dfb3b352c07efcd84bb69169232f9
```

文件放在相邻 `PubTables-1M复现/datasets/PubTables-1M-structure/`。`words` 阶段校验完整压缩包后只提取名单所需的 1000 份 JSON，不解压训练集或全部词文件。

```powershell
& '..\PubTables-1M复现\.venv-download\Scripts\python.exe' -X utf8 run_benchmark.py prepare
& '..\PubTables-1M复现\.venv-download\Scripts\python.exe' -X utf8 run_benchmark.py words
& '..\PubTables-1M复现\.venv-download\Scripts\python.exe' -X utf8 run_benchmark.py predict --threads 3
& '..\PubTables-1M复现\.venv-download\Scripts\python.exe' -X utf8 run_benchmark.py ocr --threads 3
& '..\PubTables-1M复现\.venv-download\Scripts\python.exe' -X utf8 run_benchmark.py evaluate --workers 2
& '..\PubTables-1M复现\.venv-download\Scripts\python.exe' -X utf8 run_benchmark.py report
```

`prepare` 后，`predict`、`ocr`、`words` 可独立执行。`evaluate` 默认要求三者完整结束；词信息就绪后，也可使用 `evaluate --workers 2 --wait-for-inputs`，随着预测与 OCR 输出逐图评分。此模式仍需全部 1000 张完成才结束，`report` 不接受不完整结果。全流程默认输出 `outputs/benchmark-1000-seed42/`；每个命令都支持 `--out` 指定另一目录。`--data` 可改数据根目录。

## 指标和输出

- `official-summary.json`、`current-summary.json`：全部、简单、复杂表的指标，整表完全正确数与运行失败数。
- `official-metrics.csv`、`current-metrics.csv`：每张表的四项指标、预测行列数、错误信息和耗时。
- `comparison-summary.json`、`测试结果.html`：两套结果的对比及 95% 区间。
- `official/`、`current/`：逐表 JSON、HTML、CSV。
- 新运行的 `evaluate` 还会在上述两个目录自动导出 `<表格ID>_overlay.png`，与原图尺寸和坐标一致。蓝框表示普通单元格，紫框表示跨行/跨列单元格，绿框表示文字框。官方基线绿框来自官方词信息，当前系统绿框来自 OCR，不能把两者都称作 OCR 预测。若该表推理失败，PNG 顶部会显示红色失败标记，详细原因见同名 JSON。
- `manifest.json`：固定抽样名单、文件哈希与源数据版本。
- `*-config.json`、`words-provenance.json`：源码、模型、输入及词信息的来源和摘要。

AccCon 按官方代码定义为单表 GriTS Con 恰好等于 1，再在全部样本上平均。保留原始文字的空格和换行，不做人工纠错或额外字符串归一化。GriTS 表示平均相似度，不能称为“整表成功率”。简单/复杂分类使用官方 GT 的跨行或跨列单元格数量。

预测失败以零分留在固定分母中；缺失或损坏的标准答案会中止评分，不能跳过。95% 区间使用按来源论文聚类的 bootstrap（2000 次，种子 42）。耗时统计为结构推理、OCR 与后处理的逐图计时之和，不含模型加载、结果写盘和评价指标计算，也不是整次实验的墙钟时间。并行运行阶段存在 CPU 资源竞争，不能直接与论文硬件耗时比较。

位置指标也受到边界生成规则影响：官方后处理按词框调整行列及单元格边界；当前系统先在空词信息上构造结构框，再填入 OCR 文本。GriTS Loc 的差距需要结合这个流程差异解释，不能直接当作结构模型自身定位能力的差距。

## 恢复与审核

### 给已有结果补 PNG

之前已经完成评估的目录，可以直接执行：

```powershell
& '..\PubTables-1M复现\.venv-download\Scripts\python.exe' -X utf8 run_benchmark.py render --out outputs/benchmark-1000-seed42
```

命令从保存的逐表 JSON、词/OCR 记录及原图绘制两套各 1000 张 PNG，不运行模型，不重新计算指标，也不改写已有 JSON、HTML、CSV 或配置。每处理 25 张输出一次进度；重复执行会重新绘制 PNG。图片保存为 `official/<表格ID>_overlay.png` 和 `current/<表格ID>_overlay.png`，并非下载的 ZIP 内的文件。

原始图片、XML、逐表 JSON 和词/OCR 文件必须保留在本地。发布的历史 ZIP 只含当时的 HTML/CSV/JSON 等结果，不能单独作为完整补图输入。仅凭 `render` 不会补做缺失的预测或导出，需先完成相应评估。

脚本源码变更后，旧实验仍应使用这条独立 `render` 命令补图；不要为补图重新运行旧目录的 `predict` / `evaluate`，这两个阶段会按原有机制拒绝不匹配的源码/配置。若重新做完整实验，所有阶段统一指定新的 `--out`。

相同代码、输入及配置下，重复执行阶段会复用逐图缓存。配置或源码改变时拒绝沿用旧阶段目录，使用新 `--out`；保存的历史源码快照用于审计。评分缓存绑定 prediction、OCR、XML、words 和评价配置摘要，重试某张图片后会重新计算相应分数。OCR 超时批次拆分为单图重试，单图仍失败则明确记录。

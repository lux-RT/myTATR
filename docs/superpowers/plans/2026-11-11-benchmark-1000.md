> **For agentic workers:** Use superpowers:executing-plans. The user approved the paired experiment in this conversation; continue without another approval gate.

**Goal:** Run an official-protocol TATR baseline and the existing TATR + PP-OCRv6 system on the same fixed random 1000 PubTables-1M test tables, with auditable metrics and failures.

**Architecture:** Keep the existing default ten-image application unchanged. Add a resumable benchmark entry point with a frozen sample manifest, cached official/current structure predictions, cached outputs from the existing OCR worker, and the unmodified official evaluator and GriTS functions. Use the existing Microsoft Hugging Face checkpoint for both pipelines; record this implementation choice and all preprocessing differences.

**Tech Stack:** Existing Python 3.12 / Torch 2.8 CPU / Transformers 4.57.1 environment and separate RapidOCR 3.10 environment. Official evaluator pinned to 16d124f616109746b7785f03085100f1f6247575.

**Spec:** User requests the same 1000 randomly selected test images for two versions: official baseline and current OCR integration. Deliver two sets of results suitable for the midterm report. No retraining or test-set tuning.

## Global constraints

- Dataset revision 35b1c097807e0b07ec5313879b85956b7b3890db; uniformly sample 1000 IDs without replacement from sorted official test IDs with Python random.Random(42).
- Freeze the manifest before inference; record image/XML hashes and the full population/filelist hash.
- Official protocol: longest edge 1000 using the pinned official PIL resize operation, ImageNet normalization, full softmax class argmax, thresholds 0.5, official word tokens and official postprocessing.
- Current pipeline: preserve current AutoImageProcessor, object conversion, PP-OCRv6 small at scale 2, and fuse().
- Use the same official GT cells and unmodified GriTS/AccCon evaluator. Strict content scoring, no custom text normalization.
- Missing reference data aborts scoring; prediction failures remain in the 1000-table denominator with zero scores and explicit failure records.
- Preserve existing outputs. Caches require matching configuration, inputs, source code and model digests.
- Update the existing feature/ppocr-v6 GitHub branch after checks. Data/model/raw outputs remain ignored; commit the tools, manifest and compact results/report.

## Review focus

- Duplicate or out-of-split sample IDs: reject before inference.
- Missing official words or malformed annotations: fail evaluation explicitly, never drop tables silently.
- Empty predictions: assign zero metrics while keeping the denominator fixed.
- Resumed runs with changed inputs/configuration: reject stale caches.
- Confusion between raw OCR output, structure content and paper performance: record versions and report both metrics and experimental limits.
